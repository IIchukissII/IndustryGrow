# M05 sensor / power module — pin map

- **Document type:** Hardware reference — pin map (not an ADR)
- **Date:** 2026-08-02
- **Project:** IndustryGrow
- **Subject:** Header usage, field connectors and signal conditioning for the M05-SAFETY sensor + cabinet-power module
- **Board:** `E0006-000001`
- **References:** ADR-0014 (sensor node taxonomy / sensor-module header d5), ADR-0018 (power distribution and rail monitoring), ADR-0005 (DSDL foundation), [`E0001-000003-D-pinmap.md`](E0001-000003-D-pinmap.md) (carrier side)
- **Sources of truth:** `E0006-000001.kicad_sch` / `.kicad_pcb` net list and `E0006-000001-L.csv` (BOM). MCU pin column is the carrier's, from the E0001 pin map.

## Scope

What the M05 module board does with the sensor-module header (ADR-0014 d5), what its field connectors carry, and the conditioning values firmware depends on. Module-side companion to the carrier pin map: the carrier fixes signal → MCU pin, this fixes signal → module function.

Firmware constants must agree with the **Conditioning** and **I²C addressing** tables below, and with **Notes**.

## Module header usage

E0006 mates with the carrier on J6 (24-pin) and J7 (16-pin). Only the rows below are used by this module; every other header pin is passed through untouched.

| Header | Pin | Net | Carrier MCU pin | M05 function |
|---|---|---|---|---|
| J6 | 4 | `I2C1_SCL` | PB6 | U1 TMP117 + U2 INA226 |
| J6 | 5 | `I2C1_SDA` | PB7 | U1 TMP117 + U2 INA226 |
| J6 | 15 | `GPIO_1` | PA9 | **leak-strip excitation** (via R6) — see note 2 |
| J6 | 17 | `GPIO_3` | PA15 | door reed input (via R7) |
| J6 | 18 | `GPIO_4` | PB12 | S0 energy-meter pulse input (via R2/C2) |
| J7 | 10 | `ADC_1` | PC4 | leak-strip sense (via R8/C5) |
| J6 | 1 / J7 | 1, 3, 5 | `STRAP_0` | +3V3 | rail in — see note 1 |
| J6 | 3, 6, 8, 12, 19, 24 / J7 | 2, 4, 6, 8, 9, 11, 13, 15, 16 | `STRAP_1` | GND | return — see note 1 |

**Passed through, unused by E0006:** J6 7 (`OW_DATA`), 9–11 (SPI2), 13–14 (SPI chip selects), 16 (`USART1_RX`), 20–23 (`PWM_1`–`PWM_4`); J7 12 (`ADC_2`, PC5 — spare analog input).

## I²C addressing

Both sensors share I2C1. **Neither is at its part-default address-strap position, so firmware defaults are wrong unless taken from here.**

| Ref | Part | Address | Straps |
|---|---|---|---|
| U1 | TMP117 | **0x48** | `ADD0` → GND |
| U2 | INA226 | **0x44** | `A1` → VS, `A0` → GND |

## Conditioning

| Ref | Value | Function |
|---|---|---|
| F1 | 1 A | +12 V input fuse |
| R1 | **0.1 Ω** (2512) | INA226 current shunt, across `Vin+`/`Vin−` |
| D1 | SK26AH | reverse-polarity clamp across the fused rail |
| R6 | 4.7 kΩ | leak excitation series, `GPIO_1` → electrode (upper divider leg) |
| R8 | 1 kΩ | leak sense series, electrode → `ADC_1` |
| C5 | 100 nF | leak sense filter to GND |
| D2 | BAT54S | leak-electrode clamp to GND / +3V3 |
| R7 | 1 kΩ | door reed series, J5 → `GPIO_3` |
| C4 | 100 nF | door reed debounce to GND |
| R2 | 4.7 kΩ | S0 pull-up to +3V3 |
| C2 | 100 nF | S0 debounce to GND |
| R11 + D6 | 4.7 kΩ + LED | +12 V present indicator — see note 6 |

The leak strip is the **lower** leg of a divider: `GPIO_1` → R6 → electrode → (strip) → GND, tapped through R8 into `ADC_1`. A dry strip is high-impedance and reads near full scale; conductive liquid pulls the node down. Charge path R6+R8 into C5 gives τ ≈ 570 µs.

Neither the door nor the S0 input has an external pull-up — both rely on the MCU's internal pull-up. Only the S0 line has an external pull-up (R2); the reed does not.

## Notes

1. **`STRAP_0` and `STRAP_1` are the +3V3 and GND rails on this board**, despite the names. They are *not* the module-ID straps those names carry on E0001. Confirmed by C1/C3/C5 decoupling across them and by U1's `V+`/`GND`/`ADD0` placement, which yields the TMP117's observed 0x48. The naming is a schematic-hygiene defect to correct at the next E0006 revision; until then, read these names as power.

2. **`GPIO_1` (PA9) is also `USART1_TX` on the carrier.** The leak excitation and the carrier's debug console are mutually exclusive on M05. Firmware claims the pin in `leak_init()`, so console output must be emitted before `sensors_init()`; release builds debug over SWD. `USART1_RX` (PA10, J6 pin 16) is untouched by this board. The carrier pin map's note 6 records the same conflict from the other side.

3. **Excitation must be gated, not continuous.** Permanent DC bias across the electrodes oxidises them (ADR-0018 d11). Firmware drives ~5 ms per 1 Hz sample and rests the pin **low**, so both ends of the strip sit at 0 V between samples. A driven-high idle — which is what an initialised UART on PA9 produces — is the failure mode this guards against.

4. **INA226 full-scale current is 0.8192 A**, not the 1 A the fuse suggests: the part's shunt input is ±81.92 mV, and 81.92 mV / 0.1 Ω = 0.8192 A. Firmware sizes its calibration from this, which also lands the current LSB on exactly 25 µA and `CAL` on exactly 2048.

5. **The door channel fails toward the alert.** A cut or unplugged reed lead floats `GPIO_3` high on the internal pull-up, reading "door open". An open door and a severed lead are indistinguishable, but the failure direction is safe — nuisance alert, never a false all-clear. The reed is normally-open: shut door = contacts closed = pin low = `engaged`.

6. **The +12 V indicator is wired ahead of F1.** R11 taps the input net directly, so D6 stays lit with the fuse blown. LED on means input present, *not* that the downstream rail is live — check J2 or the INA226 bus-voltage subject instead.

7. **`ADC_2` (J7 pin 12, PC5) is a spare analog input**, routed to the header but unused by this board.

## Verified on hardware

Bench bring-up 2026-08-02, `E0006-000001` on an `E0001` carrier, telemetry read over CAN at the gateway. All eight Cyphal subjects exercised against real stimulus: bus voltage 12.12 V, current 20.9 mA, power 254 mW, cabinet temperature ~27 °C, door reed toggled both directions, leak strip wetted and dried, S0 pulses counted at 3600 J each. Zero CAN bus errors.
